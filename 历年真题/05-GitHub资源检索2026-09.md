## 二、检索方法上的坑（下次复用）

1. **中文多词搜索基本失效**：`gh search repos "zhuanshengben 高数"` 返回 0 条，`"专升本 真题"` 只返回 1 条。GitHub 对中文分词支持差 → **改用单词 + topic + 逐个仓库拉文件树**。
2. **`search_repositories` 噪音极大**：搜「专升本」返回 583 条，首位是 23k★ 的 `Some-Many-Books`——描述里塞满 SEO 引流垃圾文本，一次调用吐 1.5MB。**别用 MCP 的 search_repositories 搜中文**，用 `gh search repos --json` 限定字段。
3. **按 stars 排序会召回无关库**：`"专转本"` 排序后全是 MusicPlayer2、OpenWrt 脚本等（描述里有「专」字被模糊匹配）。→ 必须人工过一遍 `fullName`。

## ⚠️ 六、检索过程中发现的本库隐患

`guangdong-zhuanshengben-resources/` **234MB 已被 Git 追踪**，其中 **27 个二进制文件**（.doc/.docx/.epub/.gif）：

```
.git 体积 312M（size-pack 222MB）
最大 blob：张宇高等数学 96MB、高数辅导讲义 59MB、高数解题指南 39MB、布鲁斯英语 epub 9.8MB
来源：commit 1ff3936 "Initial commit from zip"
```

这与 [[03-版权OCR体积解法]] 定的规则**直接冲突**（"禁止进 Git：完整官方/扫描 PDF、DOCX 原卷二进制"）。原因是 `.gitignore` 只拦了 `*.pdf` 和 `资料/**/*.docx`,**没覆盖这个目录的 `.doc/.docx/.epub`**。

**风险**：仓库虽已设私有，但 222MB pack + 机构版权资料，一旦误设公开或换号共享就是麻烦；且 clone/push 都会很慢。

**可选处理**（都需你决定，属破坏性操作）：
1. 保留现状（私有仓，自己用，不 push 远端大文件）
2. `git rm -r --cached` 移出追踪 + 补 `.gitignore` 规则 → 历史里仍在，但工作区干净，新 clone 变小
3. `git filter-repo` 重写历史彻底清除 → **需 force push,会作废已有 clone**

我倾向 **方案 2 + 把该目录移到仓库外缓存盘**,既止血又不折腾历史。等你确认。
