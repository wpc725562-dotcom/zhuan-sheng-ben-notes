## 三、⚠️ 硬伤：三处致命损坏（这是红线，不是我保守）

### 1. 花括号丢了 142 个 → **所有完整程序都不可复现**

```
左 { = 243 个        右 } = 101 个        ← 差 142 个
左 ( = 2430 个       右 ) = 2360 个       ← 差 70 个
107 页出现"左括号多于右括号"
```

**后果**：书上的例题**复制粘贴进 gcc 一定编译不过**。而这些程序正是他以后要「人肉编译」的对象 —— 一个缺 `}` 的循环，程序行为直接变了，**拿来出题等于出错题**。

### 2. 字母与数字互相污染 → 代码语义被改

同一份 `c1-1.c` 程序，在不同页被抽成三个样子：

| 页 | 抽出来长这样 | 应该是 |
|:---|:---|:---|
| 29 | `return g;` | `return 0;` |
| 30 | `return 6;` | `return 0;` |
| 30 | `int main()#include <stdio.h>` | `#include <stdio.h>` 在前 |

其他实测样本：`cl='A'`（是 `c1`）、`y=7l.82`（是 `71.82`）、`i=i+l`（是 `i+1`）、`X+Yi`（是 `X+Y;`）。

**后果**：`1`/`l`、`0`/`O`、`c1`/`cl` 这些混淆**恰好全砸在 C 语言最常考的语法点上**。他零基础，分不出哪个是书错哪个是他错。

### 3. 数学符号乱码 → 表达式题不可用

```
【4.3】(2)allb＋c&.&b—c        ← 真身：a>b+c && b-c
【4.3】(3）)!(a>b）&&!clll     ← 真身含 ||，被抽成 lll
【5.3】153=13十53十33          ← 真身：153=1³+5³+3³
【2.1】P=(l+r)n                ← 真身：P=(1+r)^n
【3.5】r三1.5                  ← 真身：r=1.5
```

**最讽刺的是**：4.3 正是「**写出逻辑表达式的值**」—— 广东专升本必考题型，而这道题的表达式在 txt 里**被彻底毁掉了**。

散文部分**可读性完好**，所以"**概念对不对、术语怎么说**"这一类，这份 txt 完全能当判卷标准。**我批改时优先引原文，不引自己的记忆。**
